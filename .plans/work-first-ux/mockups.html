Rule: a write (Edit/Write) or a worker launch in a folder outside the workspace's repos adds that folder; reads never do. Adding spawns nothing: no console, no shell, no env change for existing tabs. Why a sheet, not a page: opening a folder is a moment of intent ("I want to work on ops-platform"); the question is which piece of work. Rows are the workspace entries whose repos list contains this folder (or a worktree of the same repo), ordered open, parked, done. Overlap rules: a repo is shared by any number of workspaces (three list ops-platform; two also list bun-api; both see the one bun-api console and dev server). A chat belongs to exactly one workspace. Hygiene is a secondary view, per repo, under the fold. Flags: stale (no commit for 30 days and clean), merged (branch merged into the default, from one git branch --merged per repo, computed when the fold opens), folder gone (prunable, already known), /tmp, task (owned by tasks.json; its only action is Open task, because the task flow owns delete), and a dirty main checkout on an old branch. Actions are batched and always confirmed by a sheet that lists exactly what will run (git worktree prune; git worktree remove only for clean, merged, non-task worktrees; never --force, never a dirty tree). Nothing is deleted without that confirmation. The same list in This checkout scope is today's Worktrees mode unchanged.

Performance (freeze history respected): only the work's checkouts are polled, not all 15. Per refresh, per repo one git worktree list --porcelain (already run), then per owned checkout one git status --porcelain=v2 --branch (dirty counts and upstream ahead/behind in one call) and one git rev-list --left-right --count base...HEAD; ~36 short processes for this workspace, run sequentially per repo in one background Task with a timeout, results applied by event. Schedule: the current checkout keeps today's adaptive tier (5–30 s); the other owned checkouts sit on the slow tier (15–30 s) and only while the Git sidebar is visible in Workspace scope; otherwise a stat of index, HEAD and logs/HEAD under the checkout's gitdir decides whether git runs at all. Status output over a cap (e.g. 500 lines, the 249-dirty main) is counted, not stored. Rows show the age of their numbers. PR and CI are never fetched here.
