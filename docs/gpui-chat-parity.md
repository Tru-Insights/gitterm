# TRU-274 — Chat transcript parity checklist

Iced is the reference, including its surprising behavior. This is a static
code audit, not a visual certification. It expands [parity map §4](gpui-iced-parity.md#4-chat-area)
and the [H interaction rows](gpui-iced-interactions.md#chat-transcript-cards-and-roster);
their broad MATCH labels do not imply identical rendering or lifecycle behavior.

**Summary:** **192 items: 73 same, 102 differs, 14 missing, 3 GPUI-only.** Counts apply to the named properties, not whole features.

The ten differences a user would notice first, in suggested repair order:

1. Permission/question requests occupy transcript rows as well as the footer panel;
   permission rows print input and offered-rule JSON (R01–R03).
2. Errors have an `Error` heading and ordinary text instead of one red monospace
   box; warning and session notes also differ (N01–N06).
3. Live thinking and individual running tools start closed in GPUI; Iced opens
   them, and closes a tool when its result arrives (O01–O04).
4. Subagent activity becomes separate indented rows instead of the nested
   subagent disclosure, tool chips and latest-line preview (S01–S06).
5. Tool summaries omit the command/path and waiting badge; opened tools lack
   Iced's 320px output limit and 20,000-character live-output truncation (T03–T07).
6. Markdown changes while reading: single newlines collapse, headings use different
   sizes, raw HTML is parsed, and Markdown images render instead of becoming links
   (A02–A07).
7. Work folds lose failed counts and per-segment timing; pending requests and
   background agents can group differently (F04–F08, G04).
8. After `75f0b19`, Latest floats in the right place, but opening any disclosure
   pauses follow even when it fits; reflow retains a row offset rather than a text
   line (V03–V06).
9. Review findings lack colored P0–P3 badges, and reviewed commits use eight
   characters instead of seven with no branch-moved warning (D17–D21).
10. Find uses different highlight colors and counts, searches different card text,
    and cannot highlight/reveal each finding occurrence precisely (Q02–Q08).

## Audit scope and how to use the checklist

- Base: `04edeb8279ac3ca6fa5dc0a592beb87d8158acc5` (`origin/v6` at task creation).
- **Card, fold-click-position and Latest evidence is from `75f0b19`**, on
  `task/TRU-274-tru-274-gpui-chat-parity-cards-fold-click-positi`. References marked
  `@75f0b19` mean that snapshot, not an uncommitted branch or this document's branch.
  This audit does not merge that code. Other references are at the base.
- Repository evidence uses `file:line` anchors; comma-separated anchors refer to
  the same file. Line numbers are pinned to the snapshots above.
- Markdown defaults were also traced through the locally installed, locked public
  crates: `B/` = `gpui-base` **0.9.1** `src/text/`, `K/` = `gpui-component`
  **0.9.1** `src/text/` (versions in `gpui/Cargo.lock`). These are dependency source
  anchors, not files copied into this repository. No dependency was fetched.
- `F` is the chat font in pixels (default 15, allowed 11–22). `s(n)` means
  `F × n / 14`, exactly Iced's CSS and GPUI's `ChatAppearance::size`.
  All other numeric dimensions are pixels unless labeled `rem`, `%`, or `vh`.
  CSS margins collapse where normal block flow allows; GPUI list-row margins do
  not automatically reproduce that collapse.
- Color names in the rows use these exact shared values: base `#1e1e2e`,
  alt/input `#181825`, block `#313244`, footer `#2a2b3d`, fg `#bac2de`,
  muted/thinking `#7f849c`, accent `#89b4fa`, border `#45475a`, strong-border
  `#585b70`, user `#a6e3a1`, result `#94e2d5`, tool/peach `#fab387`,
  warn/yellow `#f9e2af`, err/red `#f38ba8` (`assets/agent_chat.html:7–29`,
  `gpui/crates/chat/src/appearance.rs:32–48`). Matching tokens do not imply that
  each renderer applies them to the same parts of a block.
- **same** applies only to the named property; **differs** describes both concrete
  behaviors; **missing** means no implemented counterpart to the Iced feature;
  **GPUI-only** means extra presentation without an Iced counterpart. A missing
  executor is not made equivalent by a preview button.
- Test names identify inspected GPUI tests, not proof that this audit ran them.
  `no` means no test asserting the row's specific property was found. Parenthetical
  qualifications identify partial coverage. Tests live under `gpui/crates/chat/src/` unless qualified
  with `gpui/crates/shell/src/`; additional `@75f0b19` tests exist only in that snapshot.
- Scope is transcript rendering and its event/import/roster/composer boundaries.
  No app, GUI fixture, screenshot, real transcript, private settings, or agent CLI
  was used for the audit. No code changes are included.

## Verification and limits

The table is an implementation checklist, not a claim that existing GPUI tests
prove parity. In particular, tests for routing/labels cannot prove CSS geometry,
default disclosure state, or selection/highlighting in newly split card bodies.
The two reported screenshot observations were confirmed from code only (R01–R03,
N01); no screenshot was inspected or taken for this audit.

Documentation validation: 192 unique item IDs, five columns per row, valid status
values and matching summary totals; all cited repository/dependency line ranges
exist, all named GPUI tests exist at the audited snapshots, and `git diff --check`
passes. The section-4 link extends the existing parity map.

Repository checks completed with **exit 0**: `cargo fmt -- --check`,
`cargo clippy -- -D warnings`, `cargo test`, `cargo build`,
`cargo clippy --features excalidraw -- -D warnings`, and
`cargo test --features excalidraw`. Also passed with exit 0:
`cargo fmt --manifest-path gpui/Cargo.toml -- --check` and
`scripts/check-gpui-deps.sh`. Cargo ran with `CARGO_NET_OFFLINE=true`.
The initial sandboxed default test run failed only because the process-group
fixture could not run `ps`; the full rerun with that permission passed.

GPUI interaction tests are **source-audited, not executed** here; no app or visual
verification was performed. Pixel alignment, native font rasterization and
platform-specific input behavior remain unverified at runtime. This document
records implementation differences; it does not fix them.
